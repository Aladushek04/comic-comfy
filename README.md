# comic-comfy

Локальный конвейер ComfyUI для иллюстраций в стиле комиксов: генерация с нуля, правка по маске,
фото → стиль, фото → рекламный арт GTA.

Здесь только то, что нельзя восстановить: графы, генератор, скрипты и правила стиля.
Модели (десятки гигабайт) не входят — они скачиваются скриптами.

## Структура

  workflow.py           сборщик графа из спецификации
  prompt.py             PromptBuilder — единственный путь сборки промпта
  guard.py              возрастная рамка (в том числе для ручных переопределений)
  cache.py              кэш описаний со схемой и версией промпта
  run.py                паспорт кадра (run.json), схема 2
  config.py             пути и настройки из env / yaml / comic_paths.json
tools/
  build_workflows.py    генератор: одно описание -> UI-JSON + API-JSON + App Mode
  photo_prompt.py       фото -> описание (VLM) -> генерация (ComfyUI), две фазы
  jobs.py               задание целиком и события для CLI и страницы
  tagger.py             WD14 дописывает в описание детали, которых VLM не назвал
  comfy_launch.py       headless ComfyUI по требованию: старт, лог, остановка
  settings.py           пути из env или extra_model_paths.yaml, без привязки к диску
  check_install.py      сверяет модели из сборок с диском и с DOWNLOADS.md

  test_web_ui.py        браузерные проверки страницы (Playwright, Chromium)

  service.py            одна очередь, состояние заданий, отмена
  catalog.py            сборки, meta.fields, списки из /object_info
  state.py              правила шагов и подписей (чистые функции)
  run.py                локальный сервер на loopback
  components/           панели страницы: фото, стили, параметры, кадры, диалоги

docs/                   дизайн, каталог моделей, планы и разборы

INDEX.md                какую сборку открывать в какой ситуации

## Требования

- Windows, NVIDIA 16 ГБ VRAM (проверено на RTX 4060 Ti).
- ComfyUI Desktop (0.45+), torch 2.12+.
- Python 3.13 из venv ComfyUI.
- Для `photo_prompt.py` — сервис описаний: любой OpenAI-совместимый (`/v1/models`,
  `/v1/chat/completions`), адрес в `LM_URL` или `lm_url` в `comic_paths.json`. Проверено на
  llama.cpp с Huihui-Qwen3.6-35B (порт 8765); LM Studio на 1234 работает как фолбэк и требует
  vision-модель (проверено: Qwen3.8-27B IQ3_M, Gemma4-12B).

## Быстрый старт

Сначала модели: `DOWNLOADS.md` (две команды, ~71 ГБ) и проверка `python tools\check_install.py`.
Пути берутся из `extra_model_paths.yaml` (образец — `extra_model_paths.example.yaml`, сам файл
в git не попадает) или переменных `COMFY_MODELS` / `COMFY_INPUT` /
`COMFY_OUTPUT`, править код не нужно. Если модели на другом диске, а `input`/`output` остаются
рядом с ComfyUI, положи `comic_paths.json` по образцу `comic_paths.example.json`; там же
`lm_model` закрепляет модель описания, а `lm_url` — адрес сервиса.

```powershell
$py = "<путь>\ComfyUI\.venv\Scripts\python.exe"
& $py tools\build_workflows.py                    # собрать графы
& $py tools\build_workflows.py --run 07_photo_thepit   # собрать и прогнать
```

Фото → стиль:

```powershell
& $py tools\photo_prompt.py --image "photo.jpg" --style thepit --generate
& $py tools\photo_prompt.py --batch "папка" --style comic --variants 3 --generate
```

Стили: `thepit`, `comic`, `jp`, `bimbo`, `gta`. Сборка 08z (GTA на Z-Image Turbo) короткого
имени не имеет: `--workflow 08z_photo_gta`; `--style gta` по-прежнему означает `08_photo_gta`.

## Веб-интерфейс

Локальная страница на NiceGUI: одно фото, стиль, сцена и варианты. Модели не запускает,
только проверяет, что сервис описаний и ComfyUI уже отвечают; бейдж пишет «LM Studio» или
«Сервис описаний» по ответу `/api/v1/models` против `/v1/models`. Тема тёмная по умолчанию,
кнопка в шапке переключает на светлую; выбор запоминается в `out\theme.json` и переживает
перезапуск сервера.

```powershell
python -m venv .venv-web
.venv-web\Scripts\python.exe -m pip install -r requirements-web.txt
ComicWeb.cmd                                  # откроет http://127.0.0.1:8080
.venv-web\Scripts\python.exe webapp\run.py --port 8090 --no-browser
```

Веб-зависимости живут в `.venv-web` и не ставятся в окружение ComfyUI. Запуск работает из
любого каталога: корень репозитория считается от `webapp\run.py`, а не от текущего каталога.

Ctrl+C останавливает сервер без трейсбека. В `.cmd` Windows может спросить «Terminate batch
job (Y/N)?» — это вопрос самого cmd, сервер к этому моменту уже остановлен; отвечайте Y.
`ComicWeb.ps1` делает то же без этого вопроса:

```powershell
powershell -ExecutionPolicy Bypass -File ComicWeb.ps1
```

### Headless ComfyUI по требованию

Страница не требует, чтобы ComfyUI был запущен заранее. Скопируйте
`comfy_launch.example.json` в `comfy_launch.json` (этот файл в git не попадает) и укажите
`main.py` и python из установки ComfyUI:

```json
{
  "main": "<путь>\\ComfyUI\\main.py",
  "python": "<путь>\\ComfyUI\\.venv\\Scripts\\python.exe",
  "port": 8199,
  "stop_after": true,
  "startup_timeout": 180
}
```

Тогда «Старт» идёт по порядку: описание фото в сервисе описаний → выгрузка VLM (если это
LM Studio; сервис на 8765 держит модель сам) → запуск headless ComfyUI → кадр → остановка
сервера (`stop_after`). На открытии страницы и на «Проверить сервисы» сервер **не**
запускается: бейдж честно пишет «ComfyUI: поднимется сам».

Пути можно задать и через env: `COMFY_MAIN`, `COMFY_PYTHON`, `COMFY_LAUNCH_CONFIG`;
`COMFY_STOP_AFTER=0` оставит сервер поднятым. Порт берётся из конфига или из
`COMFY_URL`/настроек. Лог сервера — `out/logs/comfy_server.log`.

Цена: каждый прогон платит запуск сервера и загрузку моделей (обычно +20–40 с). Если
поставить `stop_after: false`, следующий прогон стартует быстрее, но VLM и SDXL снова
окажутся в памяти вместе.

Что на странице: загрузка фото с одним превью и «Заменить фото», стиль из сборок `07_*`,
`08_photo_gta` и `08z_photo_gta`, сцена, число вариантов и «Старт» (весь цикл). Справа — этап, таймер, шаги
сэмплера, галерея кадров и «Скачать»: на десктопе настройки слева, результат справа, на узком
экране одна колонка. «Только описание», «Сгенерировать по описанию» и «Пересчитать промпт»
стоят рядом с редактором описания; расширенные настройки, промпт и журнал — в сворачиваемых
группах под формой. В расширенных: модель описания, recheck, чекпойнт генерации, сэмплер,
seed, denoise, сила ControlNet, вес стилевой LoRA, шаги, CFG и слоты LoRA с весами.

Ручные правки не попадают в кэш автоописания, а автоописание привязано к загруженному фото:
при замене фото старый автоматический текст очищается, ручной остаётся с предупреждением.
Номер задания хранится в адресе (`/?job=...`): новая вкладка открывается пустой, перезагрузка
возвращает своё задание, очередь общая и последовательная. Уточнённый кадр Recheck попадает в
галерею вторым и выбирается по умолчанию; оба файла можно скачать.


**Как поле доходит до формы** (пример — denoise):

1. В `tools\build_workflows.py` у сборки `07_photo_thepit` стоит `denoise: 0.75`.
2. `python tools\build_workflows.py` пишет это значение и привязку в
   `workflows\07_photo_thepit.api.json`: `meta.fields.denoise = {node: "13", input: "denoise",
   type: "FLOAT", default: 0.75}`.
3. Страница читает `meta` и показывает `0.75` подсказкой в поле. Поменяйте значение в
   генераторе на `0.83`, пересоберите графы, обновите страницу — в поле будет `0.83`.
   Код `webapp\ui.py` при этом не меняется.

Пустое поле значит «как в сборке», `0` — явный ноль. Значения из списков (`чекпойнт`, `LoRA`,
`сэмплер`) берутся из `/object_info` работающего ComfyUI; если файла из графа нет на диске,
он всё равно остаётся выбранным.

Обновление NiceGUI: поправьте версию в `requirements-web.txt` и повторите
`pip install -r requirements-web.txt`; после обновления проверьте `python tools\test_web_app.py`.
Для браузерных проверок поставьте `requirements-web-dev.txt` (там Playwright) и запустите
`python tools\test_web_ui.py`. Графы после `git pull` пересоберите: `*.api.json` не хранится
в репозитории. Переменные кодировки для `tools\*` не нужны: скрипты сами ставят UTF-8 на
stdout/stderr, поэтому вывод читается и в консоли, и в файле (`webapp\run.py` поднимается
из `.cmd` со своим окружением и в этот список не входит; `test_web_ui.py` задаёт переменные
дочернему серверу сам).

Состояние текущего задания отдаётся ещё и как JSON: `http://127.0.0.1:8080/api/job`
(или `?job_id=...`) — удобно, когда этап висит и нужно увидеть полный список событий.

## Что важно знать

- Стиль задаёт граф, а не языковая модель: `photo_prompt.py` подставляет субъекта в шаблон промпта
  из сборки (`meta.positive_template`), поэтому CLI и панель дают одинаковый стиль.
- Теггер WD14 дописывает в описание то, чего VLM не назвал (размер груди, ареолы, украшения,
  чулки), и убирает цвет радужки, если глаза закрыты. `--no-tags` выключает добавку,
  `COMIC_TAGGER=off` — для проверок без моделей. Свои ONNX в 23 модели сборок не входят и сами
  не качаются: `python tools\tagger_bench.py --download` кладёт их в `out\models\tagger`,
  без них добавка молча пропускается (в логе — «теггер выключен»).
- Описание кэшируется по **содержимому** файла, а не по имени, и помнит версию промпта:
  после правки SYSTEM старые описания переснимаются сами, `--force` не нужен.
- У 08z (Z-Image Turbo) CFG 1, поэтому негатив не читается: `meta.negative_effective=false`, CLI
  пишет «негатив не действует (CFG 1)», а `--recheck` на этой сборке отказывается. Рамку возраста
  держат позитив (`with_adult`) и описание VLM.
- CLIP у SDXL режет текст на чанки по 77 токенов и кодирует их подряд: длинный промпт не
  обрезается, но дальние теги влияют слабее — важное ставим в начало.
- Перед загрузкой моделей в память спрашивать разрешение (см. `AGENTS.md`).
- Civitai-токен в репозиторий не попадает: он лежит в `%USERPROFILE%\.civitai\token`.
- Панель не растёт бесконечно: задания и черновики загрузок живут сутки (и последние 30
  заданий), папки `out\jobs` чистятся сами, а кадры и их `run.json` в `out\<фото>_<хэш>\`
  остаются навсегда. Загрузка больше 8192 px по стороне или 64 Мпикс отвергается до
  декодирования — с числами в сообщении.

## Для ИИ-агентов

Этот блок — краткая карта для агента, который впервые открыл репозиторий. Полные правила,
пути и разбор прошлых ошибок — в `AGENTS.md`; он главнее этого блока, если они разойдутся.

**Сначала прочитать `AGENTS.md`.** Там разделы «Нельзя без явной просьбы», «Грабли, на которые
уже наступали» (нумерованные, с симптомами и проверками) и «Проверки перед словом готово».
Без него легко сломать то, что уже чинили.

**Память и железо.** 16 ГБ одной карты: VLM и SDXL вместе не живут. Перед загрузкой модели,
запуском сервиса описаний или ComfyUI — спросить разрешение и дождаться ответа. Нельзя
поднимать LM Studio «на всякий случай»: `lms ps` и `lms status` сами запускают сервис, это
тоже запуск. Если сервис описаний на `LM_URL` не отвечает — доложить и ждать, а не искать
фолбэк самостоятельно.

**Графы генерируются, а не редактируются.** `workflows/*.json` — вывод
`tools/build_workflows.py`. Правка JSON руками теряется при следующей сборке; менять надо
`comic/builds.py` (данные) или `comic/workflow.py` (сборщик), потом пересобрать и прогнать
`tools/check_widgets.py`. `*.api.json` в git не хранится — после `git pull` графы
пересобираются. Копию для панели ComfyUI обновляет `tools/sync_panel.py` (только из
репозитория); править папку панели руками бессмысленно — следующий `sync` её перезапишет.

**Пути не хардкодятся.** Никаких `G:\...` в коде и скриптах: только `comic/config.py` /
`tools/settings.py`, то есть env (`COMIC_ROOT`, `COMFY_MODELS`, `COMFY_SHARED`, `COMFY_INPUT`,
`COMFY_OUTPUT`, `COMFY_URL`, `LM_URL`, `LM_MODEL`), `extra_model_paths.yaml`,
`comic_paths.json`, `comfy_launch.json`. Эти файлы машинные и в git не попадают —
образцы лежат рядом с ними (`*.example.*`).

**Успех — это файл, а не `status_str`.** `success` с пустым `outputs` бывает и означает провал.
Признак кадра — имя файла в `outputs`; CLI и `build_workflows.py --run` возвращают код 1 при
любом провале, поэтому смотреть `$LASTEXITCODE`, а не строку «готово» в логе.

**Проверки и их окружения.** `tools/test_photo_prompt.py` (~724) — из venv ComfyUI, модели не
нужны. `tools/test_web_app.py` (~344) и `tools/test_web_ui.py` (~99, Chromium через Playwright) —
из `.venv-web`, иначе падает `ModuleNotFoundError: nicegui`: это не поломка кода, а не то
окружение. Отдельно `tools/check_install.py` (все 23 модели на диске и в `DOWNLOADS.md`) и
`tools/sync_panel.py --check` (копия графов для панели не разъехалась).

**Возрастная рамка несъёмная.** `comic/guard.py` вырезает `young/teen/girl/boy/1girl/school`
и ставит `adult woman|man` первым тегом, негатив всегда кончается `NEG_GUARD`. Переопределения
пользователя проходят через ту же рамку. Ослаблять её нельзя ни по просьбе, ни «для теста».

**Не мешать прогону.** Долгие команды писать в файл и читать хвост, а не в пайп с
`Select-Object`: обёртка зависает. Задания и кадры живут в `out\` (в git не попадает);
`run.json` и кэш описаний писать только через `photo_prompt.write_json` — обычная запись рвёт
файл пополам. `--dry-run` не грузит модель и не трогает ComfyUI, но требует готового описания
(кэш, `--preset`, `--from-json`, `--no-llm --subject`), иначе отказывается с кодом 1.

**Где искать причину.** Паспорт кадра — `out\<фото>_<хэш>\run.json` (сборка, seed, denoise,
фактические positive/negative). Лог headless ComfyUI — `out\logs\comfy_server.log`. Состояние
задания целиком — `http://127.0.0.1:8080/api/job?job_id=...`. Сборки и их назначение —
`INDEX.md`, правила стиля — `STYLE.md`, модели и почему выбраны — `docs/models.md`.
