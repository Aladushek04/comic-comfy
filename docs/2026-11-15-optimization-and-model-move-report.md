## Исходные данные

- Модели ComfyUI сейчас находятся в `G:\Comfy-Desktop\ComfyUI-Shared\models`: 47 файлов, 110 321 594 070 байт (102,74 ГиБ). Размер получен перечислением файлов, без чтения моделей в память.
- **Для переноса нужны две настройки моделей.** `%APPDATA%\Comfy Desktop\settings.json` → `modelsDirs` задаёт каталог для Desktop. `extra_model_paths.yaml` → `base_path` задаёт каталог для headless ComfyUI и проекта (`tools/settings.py` читает его, если не задан `COMFY_MODELS`). Desktop использует свой сгенерированный `instance-model-paths\inst-*.yaml`, а не репозиторный YAML; сгенерированный файл не редактировать.
- Сейчас Desktop задаёт `inputDir` и `outputDir` в той же `settings.json` на G: и передаёт их ComfyUI явно. Headless ComfyUI передаёт `--input-directory` и `--output-directory` из `tools/settings.py`; без отдельных значений `settings.py` выводит их из родителя каталога моделей. Перенос моделей не должен переносить `input` и `output`.
- E: подтверждён как Samsung SSD 970 (Disk 4, NVMe), G: — AMD R5SL480G (Disk 2, SATA); оба NTFS, Healthy. Свободное место E: при проверке 2026-11-16 — 460 629 209 088 байт (429,0 ГиБ); перед копированием проверить снова. Каталог моделей занимает 102,74 ГиБ; символических ссылок/junction в нём нет.

Если этот параметр важен для эксплуатации, проверить его через оснастку Windows. После переноса оба конфига будут зависеть от стабильности буквы E:; закрепить её и проверять после изменения состава дисков.

- Часть весов лежит вне общего каталога моделей: `custom_nodes\comfyui_controlnet_aux\ckpts` внутри установки ComfyUI на G: (1,58 ГиБ) и `models` внутри установки (0,35 ГиБ). Модели LM Studio уже находятся в `E:\LM Studio Models` и не входят в подсчитанные 102,74 ГиБ. Перенос общего каталога не ускорит загрузку этих весов.

## Что измерить до изменений

Снять три повтора на одном фото и одной сборке, отдельно для холодного старта ComfyUI и для уже работающего сервера. Зафиксировать ревизию графа: последние правки меняли подсказки для смены сцены в `07_photo_*`, а будущие правки могут менять параметры. Для генераций менять seed: одинаковые seed и граф дают попадание в кэш ComfyUI и искажают замер. Записать:

| Этап | Что фиксировать |
| --- | --- |
| VLM | выбор/загрузка модели, описание фото, переписывание сцены при наличии, выгрузка |
| ComfyUI | запуск процесса, готовность API, загрузка checkpoint/LoRA/ControlNet, первый шаг, все шаги, запись кадра |
| Приложение | подготовка фото, копирование в input, построение графа, ожидание `/history`, копирование результата, запись `run.json` |

Фиксировать общее время задания через монотонные часы, а также размер файлов и пиковые RAM/VRAM. Нынешняя строка итога в `tools/jobs.py` складывает `t_desc + t_unload + t_gen`, но не включает запуск ComfyUI, переписывание сцены и часть подготовки. Использовать `Emitter.elapsed` как полный итог и отдельные таймеры по этапам. Существующие замеры в `docs/2026-11-12-comic-stack-design.md` показывают преимущество быстрой Qwen-сборки (102 с против 375–397 с), но не являются замером эффекта переноса диска.

Любой запуск VLM, ComfyUI или генерации для замеров — только после отдельного согласия Maker на загрузку памяти. Статические проверки, перечисление файлов и проверки путей согласия не требуют.

## План переноса моделей

1. Проверить **текущее** свободное место E:, отсутствие активных загрузок `.part` и ComfyUI. На момент проверки 2026-11-16 порты 8188/8199 были свободны, но состояние может измениться. Загрузки остановить до копирования. `COMFY_*` переменные сейчас не заданы; их значения повторно проверить в среде каждого запуска.
2. Скопировать `G:\Comfy-Desktop\ComfyUI-Shared\models` в `E:\ComfyUI-Shared\models` **без удаления источника**, например `robocopy ... /E` без `/MOVE`, `/MIR` или удаления. Сохранить структуру подпапок и имена файлов. После копирования сверить относительные пути, количество, размеры и SHA-256 каждого файла; несовпадение исправить до переключения.
3. До переключения выполнить `tools/check_install.py --models E:\ComfyUI-Shared\models`; убедиться, что все 22 модели, требуемые текущими сборками, лежат в нужных разделах. Остальные 25 файлов эта проверка не охватывает: целостность **всех 47** доказывает только полная сверка SHA-256 из шага 2. Проверить путь назначения загрузчиков HF/Civitai: они берут `COMFY_MODELS` либо `base_path`.
4. После успешной сверки закрыть Desktop и изменить **оба** источника пути моделей. В настройках Desktop **заменить** единственный элемент `modelsDirs` на `E:\ComfyUI-Shared\models`, не добавлять E: вторым каталогом рядом с G: (дубли моделей). `base_path` в `extra_model_paths.yaml` тоже заменить на E:. Desktop `inputDir` и `outputDir` оставить на G:. Настройки Desktop предпочтительнее правки `settings.json` вручную: не подтверждено, что простое редактирование JSON при закрытом приложении обновит его сгенерированный YAML.
5. Отвязать пути `input`/`output` проекта от `models_dir.parent`. Для реализации использовать локальный `comic_paths.json` в корне проекта, по образцу `comfy_launch.json`: два строковых абсолютных пути `input` и `output` (формат ниже). Добавить в Git `comic_paths.example.json`, а `comic_paths.json` — в `.gitignore`; не зашивать диски в Python. Приоритет для каждого пути: явный `COMFY_INPUT`/`COMFY_OUTPUT` → заданный через env `COMFY_SHARED` плюс соответствующая подпапка → поле `comic_paths.json` → прежний запасной путь `models_dir.parent/input` или `/output`. Путь моделей независимо выбирается как `COMFY_MODELS` → `base_path` → раскладка рядом с репозиторием. Таким образом env `COMFY_*` остаются сильнее локального файла, а файл сильнее вывода из `base_path`. Временный вариант без правки `settings.py` — задать `COMFY_SHARED=G:\Comfy-Desktop\ComfyUI-Shared` или оба `COMFY_INPUT`/`COMFY_OUTPUT` для `ComicWeb.cmd`, `ComicWeb.ps1` и прямого CLI; одного `base_path` недостаточно. Проверить `settings.resolve()` и `comfy_launch.plan()` без запуска моделей. Обновить `tools/test_photo_prompt.py`, пункт 13: нынешнее утверждение «input/output рядом с models» проверяет старое правило и после отвязки должно быть заменено осмысленной проверкой независимых путей, а не восстановлено ради проходящего теста.
6. После разрешённого запуска Desktop проверить именно YAML, переданный ComfyUI через `--extra-model-paths-config` (сейчас это `%APPDATA%\Comfy Desktop\instance-model-paths\inst-1794510985662.yaml`): `base_path` должен указывать на `E:\ComfyUI-Shared\models`. Не редактировать генерируемый YAML вручную. Если там остался G:, остановиться и исправить настройку через Desktop; `/object_info` сам по себе не доказывает, из какого каталога показаны одноимённые файлы. Затем проверить `/object_info`, `LoadImage`, `SaveImage`, `save_run`, recheck и веб-превью на прежних `input`/`output`. Проверить все 14 графов. Если сервер ещё не запущен, не поднимать его только ради проверки без согласия Maker.
7. После согласия Maker выполнить один холодный и один тёплый прогон с новыми seed. Сравнить с базой, проверить фактический кадр в `OUTPUT_DIR` и запись `run.json`. Старую папку на G: не удалять до принятия результатов и отдельного решения Maker.

**Откат:** вернуть прежние `modelsDirs` и `base_path`, а также прежнюю настройку путей `input`/`output`, затем перезапустить процессы; исходная папка на G: остаётся целой. При откате не переносить и не удалять `input`, `output`, `out` и `run.json`.

Предлагаемое содержимое локального `comic_paths.json` (сам файл создаётся только при реализации):

```json
{
  "input": "G:\\Comfy-Desktop\\ComfyUI-Shared\\input",
  "output": "G:\\Comfy-Desktop\\ComfyUI-Shared\\output"
}
```

## Оптимизация кода после базового замера

| Приоритет | Изменение | Основание и критерий |
| --- | --- | --- |
| P0 | Сделать точный тайминг этапов и полного задания | Без него нельзя приписать ускорение диску или коду. Сравнение до/после — на тех же сборках, фото и числе вариантов, с новыми seed. |
| P1 | Делать первую проверку `/history` сразу; при наличии WebSocket будить следующую по `comfy_done` или `comfy_error`, периодический опрос оставить запасным путём | `wait_for_prompt()` в `tools/photo_prompt.py` сейчас делает `sleep(3)` даже перед первым запросом истории. В CLI WebSocket может отсутствовать, поэтому мгновенная первая проверка нужна и там. Сохранить правило: успех только при реальном имени файла в `outputs`. Проверить обрыв WebSocket, пустой `outputs` и завершение без события. |
| P2 | Вычислять `ensure_input()` и ориентацию фото один раз на фото перед циклом вариантов | В `tools/jobs.py` `ensure_input()` вызывается для каждого варианта; пакетный CLI также повторяет `image_is_landscape()` и `ensure_input()` внутри цикла. Два и более варианта должны получать одно имя input без повторной проверки и копирования. |
| P2 | Кэшировать разобранный шаблон API-графа по пути и времени изменения, перед подстановкой делать отдельную копию | `build_payload()` каждый раз вызывает `load_workflow()` и `check_bindings()`. Кэш не должен смешивать настройки параллельных заданий и обязан инвалидироваться после пересборки графа. Ожидаемый эффект небольшой; оценить по таймеру. |
| P3 | Измерить и затем сократить повторные PNG-перекодирования/копии фото | Веб-загрузка пересохраняет фото до 4096 px, VLM уменьшает его до 1280 px, `submit()` и `ensure_input()` создают копии. Сохранить валидацию размера, EXIF и изоляцию заданий. Менять только если измерения покажут значимый расход. |

Не объединять перенос и оптимизацию в один неделимый шаг: после переноса снять повторный замер, затем оценивать каждое изменение кода отдельно. Это позволит увидеть реальный вклад NVMe и быстро откатить регрессию.
