# ComicPit-V2: пересборка проекта

Дата: 2026-11-16. Статус: на утверждение.
Основание: `docs/2026-11-16-comicpit-v2-audit.md` (четыре аудита + прогон проверок),
`docs/2026-11-16-generation-models-market.md`, `docs/2026-11-16-cv-models-market.md`.

## 1. Зачем

Конвейер работает и делает то, что нужно: фото → описание VLM → теги WD14 → SDXL/Illustrious
с LoRA стиля и ControlNet глубины → кадр с паспортом. Но менять его дорого: `photo_prompt.py`
держит пять забот в 1455 строках, сборка промпта существует в двух вариантах (CLI и веб),
`run_batch` — третий, а интерфейс мутируется по месту (41 `set_text`, 108 литеральных
`classes`, полная перерисовка каждые 600 мс).

Цель V2 — не новые возможности, а **цена следующего изменения**. После V2 добавление базы,
стиля или поля должно быть правкой в одном месте, а не в четырёх.

## 2. Цели

1. **Один путь сборки промпта.** `--dry-run`, CLI, панель и `--batch` дают побайтно тот же
   positive/negative для тех же входов.
2. **Типизированное ядро.** Конфиг, запись прогона и кадр — dataclass'ы, а не словари и
   глобальные константы, замороженные на импорте.
3. **Паспорт, который объясняет кадр.** `steps`, `cfg`, `sampler`, оба прохода, метка
   исхода, версия схемы. Сейчас двух кадров с одинаковыми записанными параметрами
   достаточно, чтобы это опровергнуть.
4. **Декларативные сборки.** Таблица «база, LoRA с ролями и триггерами, промпты,
   разрешение, сэмплеры, поля App Mode» вместо хирургии словарей и поиска LoRA по весу 0.9.
5. **Интерфейс, который толкает состояние.** SSE вместо опроса, компоненты вместо
   мутации виджетов, тёмная тема без мигания, история кадров из `run.json`.
6. **Безопасность в одном месте.** Возрастная рамка применяется к описанию, к негативу
   **и к пользовательским переопределениям** — сейчас переопределения её снимают.

## 3. Не-цели

- Новые базы генерации (08 на Z-Image, 07 на другой базе) — отдельный этап после V2.
- Советник параметров (VLM подсказывает denoise/вес/шаги) — отложен, раздел 8 аудита.
- Переписывание теггера, `check_install`, `comfy_launch`, разрешения путей.
- Изменение смысла графов: те же узлы, те же значения по умолчанию, тот же текст промптов.
- Мобильное приложение, многопользовательский режим, облако.

## 4. Анти-цели

- Потерять хотя бы одну из 489 проверок или любое поведение из списка грабель `AGENTS.md`.
- Изменить текст промпта для тех же входов (кроме исправления `theofficialpit style`).
- Удалить модели до того, как A/B задокументирован.
- Скрытые изменения поведения: всё, что меняется, попадает в `AGENTS.md` и в проверку.

## 5. Ограничения

- 16 ГБ GPU, одна модель в памяти; VLM выгружается до ComfyUI.
- Python 3.13 (venv ComfyUI) / 3.14 (venv-web), NiceGUI 4.0.0 — последняя версия, обновлять некуда.
- Windows, PowerShell, пути только через env или yaml (`test_portable_paths` запрещает литералы диска).
- Русский интерфейс и русские сообщения об ошибках.
- Только взрослые вымышленные персонажи; рамка не должна сниматься флагами.

## 6. Подходы

1. **Только лицо.** Новый UI поверх нынешних `service.py`/`jobs.py`. Дешево, но 1455-строчный
   `photo_prompt.py` и два пути промпта остаются — через полгода тот же разговор.
2. **Лицо и ядро, вытеснением (выбран).** Новый пакет `comic/` рядом с `tools/`; старые точки
   входа продолжают работать, пока модуль за модулем не переключимся. Тесты переезжают
   вместе с поведением и остаются страховкой.
3. **Всё сразу, большим взрывом.** Новый репозиторий, старый в архив. Чисто, но теряем 489
   проверок как доказательство и повторяем грабли, записанные в `AGENTS.md`.

Выбран второй: он единственный сохраняет доказательство работоспособности в момент, когда
оно нужнее всего.

## 7. Как это устроено

### 7.1 Пакеты

```
comic/                     ядро, без NiceGUI
  config.py                Config (dataclass): пути, LM, ComfyUI, флаги. Создаётся один раз
  describe.py              клиент VLM: провайдер, /no_think, два изображения, JSON, санитайзеры
  prompt.py                PromptBuilder: positive/negative/applied — единственный путь
  cache.py                 запись кэша с версией схемы и миграцией
  comfy.py                 клиент ComfyUI: /prompt, /history, WS, разбор ошибок
  run.py                   RunRecord, PassRecord, save/read run.json (схема 2)
  workflow.py              декларативная спецификация сборки → граф + meta
  jobs.py                  оркестрация: run_job на описанных выше модулях
  guard.py                 with_adult, NEG_GUARD, scrub_tags — применяется ко всем путям
web/                       интерфейс
  app.py                   точка входа NiceGUI, маршруты
  components/              upload, style_picker, job_card, progress, gallery, advanced
  service.py               очередь (переносится, + cancel)
  state.py, catalog.py     переносятся как есть
tools/                     тонкие обёртки CLI над comic.*, стенды, загрузчики
```

`pyproject.toml` появляется; `sys.path.insert` и импорт внутри функции для разрыва цикла
исчезают вместе с циклом: `jobs` больше не импортирует `photo_prompt`.

### 7.2 Ключевые решения

- **`Config` передаётся явно.** Никаких `settings._PATH` и `pp.LM`, замороженных на импорте;
  тесты перестают подменять 34 глобальных имени и начинают передавать объект.
- **`PromptBuilder.build(photo, meta, fields) -> (positive, negative, applied)`.** Один
  вызов для предпросмотра, CLI, панели и пакета. Поле `landscape` и имя файла входят
  в аргументы, поэтому предпросмотр перестаёт отличаться от кадра.
- **`RunRecord` схема 2:** `schema`, `workflow`, `seed`, `passes[{denoise, steps, cfg, sampler}]`,
  `cn_strength`, `style_weight`, `overrides`, `outcome`, `positive`, `negative`, `file`.
  Старые записи читаются миграцией: `passes` собирается из `denoise` + зашитого hires 0.3.
- **Декларативная сборка:** `Build(base=..., loras=[Lora(file, role, weight, trigger)], prompts=...,
  resolution=..., samplers=..., app_fields=..., style_slot=...)`. `_swap_style`, `_add_hands`,
  `_tune_bimbo` и патч 03b заменяются данными. Стиль ищется по роли, а не по весу 0.9.
- **`guard.py` — единственное место рамки.** `sanitize_subject()` применяется к описанию VLM,
  к переопределению positive и к `--subject`; `ensure_guard(negative)` дописывает
  `NEG_GUARD`, если его нет. Переопределение больше не снимает рамку.
- **UI толкает состояние.** Один SSE-канал на задание; `ui.timer` остаётся только как
  страховка при обрыве. Компоненты — отдельные модули, стили — токены Tailwind, а не
  литеральные классы в 108 местах.
- **Отмена и пресеты** входят в `JobRequest` и в очередь.

- `theofficialpit style` в трёх сборках из четырёх — промпт спорит с LoRA.

### 7.5 Тесты и их цена

Замерено на этой машине 16.11.2026:

| Набор | Проверок | Время | На проверку |
|---|---|---|---|
| `test_photo_prompt.py` | 273 | **4.5 с** | 16 мс |
| `test_web_app.py` | 181 | **37.6 с** | 208 мс |
| `test_web_ui.py` (Chromium) | 35 | ~2 мин | ~3 с |

Вывод: **дороги не проверки, а обвязка.** 273 проверки стоят 4.5 секунды; 37.6 секунды
в `test_web_app.py` — это 24 тестовые функции, каждая из которых поднимает свой
`ThreadingHTTPServer` и ждёт его в цикле с `sleep(0.02)`. Браузерные 35 — самая дорогая
часть, потому что каждая идёт через реальный Chromium и сервер.

Поэтому в V2 три уровня с бюджетом, а не один общий прогон:

| Уровень | Что входит | Бюджет | Когда гонять |
|---|---|---|---|
| **T0 fast** | чистые функции: промпт, кэш, guard, полки теггера, правила шагов, `collect()`, разбор `run.json` | **≤5 с** | на каждое сохранение |
| **T1 app** | HTTP-заглушки, жизненный цикл задания, очередь, отмена, паспорт | **≤15 с** | перед коммитом |
| **T2 ui** | Chromium: рендер, клики, тёмная тема, две вкладки, обрыв WS | **≤2 мин** | перед словом «готово» и перед релизом |

Как это получается:

1. **pytest вместо самодельного раннера.** Сейчас нельзя запустить одну проверку по имени.
   Маркеры `fast`/`app`/`ui`, `-x`, `-n auto`; по умолчанию `-m "not ui"`.
2. **Один сервер-заглушка на сессию** вместо 24. Это и есть основной выигрыш в T1:
   37.6 с → примерно 10–15 с без изменения содержания проверок.
3. **Логика уезжает из обработчиков.** Сейчас 35 браузерных проверок нужны потому, что
   решения живут внутри виджетов: `collect()`, белый список `media_job`, `render_result`,
   `desc_auto`. После выноса в чистые функции они проверяются в T0 за миллисекунды,
   а в T2 остаются 8–10 сценариев «нарисовалось и нажимается».
4. **Правило бюджета.** Новая проверка идёт в самый быстрый уровень, который её выражает.
   Если она требует сервера — в T1; если браузера — в T2, и тогда её цена обсуждается
   отдельно. T0 за 5 секунд — жёсткий бюджет, его нельзя превышать.
5. **Подпроцессы** (`build_workflows`, `check_install`) помечаются `slow` и идут в T1,
   а не в общий прогон.

Проверки из списка `AGENTS.md` 0.14 остаются все, но распределяются: имена этапов,
фильтр шагов по `meta.samplers`, `upload.reset()`, номер задания в адресе, отказ WebSocket
проверяются на T1 после выноса логики; тёмная тема, раскладка и две вкладки — на T2.

**После V2, отдельным этапом (V2.1):**

- **08 на Z-Image Turbo.** База: AIO FP8 10 ГБ (VAE и TE внутри) или int8 6.20 ГБ + TE.
  Стиль: наш же GTAV-порт `ZImageTurbo` v2513561, 162 МБ. Контроль: Fun ControlNet Union 2.1
  (lite 1.9 ГБ или полный 6.71 ГБ) с depth. Новый граф: 8 шагов, CFG 1, `res_multistep`/`simple`.
  Два следствия, которые надо принять заранее: **при CFG 1 негатив не работает** (значит
  `NEG_GUARD` и `--recheck` теряют рычаг), и промпт нужен на естественном языке, а не тегами.
- **07 остаётся на Illustrious, но появился путь на Anima.** Проверено 16.11.2026:
  у ThePit есть порт на Anima — `civitai.com/models/2811081` (ToasterKing, v3170125,
  88 МБ, база Anima, 435 загрузок, без триггера). У нашего TheOfficialPit порта на Anima
  пока нет, но его автор Gereccan уже переносит другие свои стили в пары
  «Anima / Illustrious» (Julius Zimmerman, Garabatoz, Jinnsart, Tagu, Monstrousfrog,
  FrootNSFW, Screwroot) — то есть направление понятно. Не хватает второй половины:
  у Anima нет depth-ControlNet, только community VACE-Canny. Условие переезда 07:
  порт TheOfficialPit под Anima **и** ControlNet с глубиной.

**Не трогаем в V2:** `WAI-17` (официальная Illustrious v3.0-ε существует, но файла в
открытом доступе нет, а чистая база без NSFW-финетюна нам не годится), LoRA jp/comic/bimbo
(портов нет), теггер WD14 (2.6 с на CPU, работает).

Проверено 16.11.2026: наш `WAI-Nsfw-Illustrious-17.safetensors` — 6617 МБ, SHA256
`F116B0C7…0BD04`, совпадает с Civitai v17.0 (model 827184, version 2883731). Это
оригинал, не пересборка. Существует fp8-перепаковка того же v17.0 —
`Quiho/WAI-illustrious-HSWQ_v17.0_base_checkpoint` (4.75 ГБ, 407 загрузок) и
«WAI-illustrious-HSWQ» на Civitai (7 тыс. загрузок). Это **не апгрейд качества**,
а экономия 1.7 ГБ на чтении с диска и в VRAM; берём только если упрёмся во время
загрузки чекпойнта, и только через A/B на фиксированном сиде.

**Правила любой замены модели или LoRA:**

1. Файл не подменяется на месте: старый уходит в `models\_archive\`, новый кладётся рядом.
2. Записываются sha256 и точный размер; `check_install` сверяет их, а не имя.
3. A/B на фиксированном сиде и одном фото, с diff по `run.json`, а не «на глаз».
4. Сверяются триггеры: у каждой версии LoRA они свои, и `meta.style_lora` матчится по имени файла.
5. Замеряется время кадра и пик VRAM: замена меняет не только качество.

### 7.7 Решения по вопросам ревьюера

| Вопрос | Решение |
|---|---|
| `--batch` умирает вместе с `run_batch`? | Нет. Удаляется **реализация** `run_batch`, а флаг `--batch` остаётся и переезжает на `jobs.run_job`: два прохода (все описания → выгрузка VLM → генерация) сохраняются, проверки на пакет тоже |
| Как `comic/` становится импортируемым? | Без установки в venv ComfyUI. Один `sys.path.insert(ROOT)` в двух точках входа (`tools\photo_prompt.py`, `webapp\run.py`), всё остальное импортирует `comic.*`. Командные строки в документации не меняются |
| Кто переписывает 273/181 и что считается «зелёным» на фазе? | P1–P4 идут на **старых** тестах без правок: старые глобалы остаются тонкими алиасами. Переписывание тестов на `Config` — отдельная фаза P4.5, после того как ядро готово. Гейт фазы — существующие наборы зелёные |
| Байтовое равенство промптов против разрешённого фикса | Golden-файлы снимаются в P0, **до** фикса. В список разрешённых расхождений входят четыре сборки: `07_comic`, `07_jp`, `07_bimbo` и `01_scene_comic`/`01_scene_jp` (там та же ошибка). Diff ревьюится как единственное разрешённое изменение |
| Что такое baseline P0 и критерий приёмки? | Матрица: одна фотография, два сида, пять сборок (`07_thepit`, `07_comic`, `07_jp`, `07_bimbo`, `08_gta`). Критерий — **не** побитовое равенство: совпадение текста промпта побайтно, diff `run.json` по параметрам и просмотр двух кадров на сборку. Побитовое равенство на GPU недостижимо |
| `03` удаляем или чиним рамку? | Удаляем: правка фото признана неактуальной. Стек в архив, графы `03_*` из репозитория. Правка рамки в `03` не делается — работы нет |
| Что делает отмена? | POST `/interrupt` в ComfyUI и освобождение GPU; частичный кадр не сохраняется; задание в очереди снимается без запуска. В паспорт попадает `outcome: cancelled`, только если кадр успел появиться |
| Кто пишет `outcome` и какие значения? | Значения: `accepted`, `rejected`, `refined`, `cancelled`, `unknown`. Пишут: `_recheck` → `refined`; действие пользователя в галерее → `accepted`/`rejected`; отмена → `cancelled`; старые записи → `unknown`. Действия в галерее входят в P5 |
| Миграция старых `run.json`: откуда второй проход? | Из самой сборки, а не из константы 0.3: у `01_scene_thepit` второй проход 0.45, у `07`/`08` — 0.3, у `06` один проход. Если сборку восстановить нельзя — `null` и `estimated: true` |
| `01` остаётся в CLI? | Открытый вопрос к пользователю. Если да, `PromptBuilder` получает путь без фото и `--prompt`, и `01` входит в набор байтового равенства; если нет — `STYLE_PREFIX` удаляется |

## 8. Что остаётся на усмотрение исполнителя

- Имена модулей внутри `comic/` и `web/components/`.
- Транспорт SSE: `ui.run_javascript` + EventSource или встроенный механизм NiceGUI.
- Разбиение тестов: сохранить три файла или разделить по модулям.
- Формат golden-файлов промптов.
- Порядок фаз P1–P4 можно менять, если тесты остаются зелёными на каждом шаге.

## 9. Риски

| Риск | Как ловим |
|---|---|
| Дрейф промптов | golden-файлы: те же входы → те же байты |
| Осиротение истории `out\<фото>_<хэш>` | длина `fingerprint` заморожена, тест на чтение старых папок |

| Снос моделей необратим | сначала `models\_archive\`, удаление через неделю |
| NiceGUI 4.0.0 не обновится | проверки на семантику, не на DOM-классы |
