# P0: паспорт кадра и baseline

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `run.json` объясняет кадр полностью — шаги, cfg, сэмплер, оба прохода и метка исхода — и на этом формате снят baseline для сравнения после пересборки.

**Architecture:** Правки только в существующем коде (`tools/photo_prompt.py`, `tools/jobs.py`, `webapp/service.py`): новые поля добавляются к записи, которую уже пишет `save_run`, значения берутся из собранного payload, а не из аргументов. Baseline — отдельный прогон через CLI на фиксированных сидах.

**Tech Stack:** Python 3.13, стандартная библиотека, PIL, существующие самодельные проверки (`tools/test_photo_prompt.py`, `tools/test_web_app.py`).

**Spec:** `docs/superpowers/specs/2026-11-16-comicpit-v2-design.md`, разделы 7.2 и 7.7.

## Global Constraints

- Ничего не менять в текстах промптов: P0 только пишет поля.
- Старые `run.json` обязаны читаться без ошибок.
- Новые поля обязаны появиться и в CLI, и в веб-пути: оба идут через `save_run`.
- Русские сообщения об ошибках и логи — как в проекте.
- Тесты: `tools/test_photo_prompt.py` (273) и `tools/test_web_app.py` (181) остаются зелёными.

## Review Focus

- Кадр, у которого второй проход записан как первый (или наоборот) — паспорт снова врёт.
- `denoise: null` в старом паспорте не должен превращаться в 0.0 или в чужое число.
- Запись через веб-путь не должна терять новые поля из-за белого списка в `service.py`.
- `outcome` не должен ставиться «accepted» по умолчанию: по умолчанию `unknown`.
